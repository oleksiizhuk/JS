# Формат страницы темы в собес-тренажёре

Проект: `react-interview/` (Vite + React). Каждая страница темы строится как
«мини-собеседование» в строгом порядке. Образец: `src/topics/js/LetVarConst.jsx`.

## Структура страницы (обязательный порядок)

1. **`<InterviewQuestion en="...">`** — вопрос так, как его задаст интервьюер
   («В чём разница между X и Y?»). ДВУЯЗЫЧНЫЙ: русский — children,
   английский — проп `en` (строка). Язык переключается тумблером RU/EN в
   сайдбаре (LangContext).
2. **`<ModelAnswer en={<>...</>}>`** — эталонный ответ, который хочет услышать
   интервьюер. ДВУЯЗЫЧНЫЙ: русский — children, английский — проп `en` (JSX):
   - от первого лица, в кавычках «...» (англ. — "..."), как связная устная речь
   - 4–7 предложений, ключевые термины выделить `<b>`
   - в конце — практический вывод («в новом коде делаю так, потому что...»)
   - английская версия — полноценный перевод той же структуры, не сокращение
3. **`<SectionTitle>Разбор с примерами</SectionTitle>`** + 2–4 демо:
   - для JS-тем — компонент `Demo` из `js/JsDemo.jsx`: код на странице,
     кнопка «▶ Выполнить», реальный вывод, `hint` с объяснением
   - для React/Redux-тем — интерактивные карточки со счётчиками рендеров
     (`useRenderCount` из `helpers.jsx`), логами (`LogPanel`), бейджами
   - для TS — `Demo` там, где эффект виден в JS-рантайме (`as` не проверяет,
     `Omit` пропускает опечатку, `!` не спасает от null); статика — только для
     чисто типовых конструкций без рантайм-следа
   - для тем без браузерного рантайма (React Native, GraphQL-сервер) — статичные
     карточки `<pre className="code">`; это норма, `Demo` не выдумывать
   - **код ВСЕГДА виден рядом с демо** (`<pre className="code">`): интерактивная
     часть без кода непонятна — юзер должен видеть, что именно сравнивается.
     Подсветка синтаксиса применяется автоматически (`src/highlight.js`)
   - **показанный код обязан совпадать с исполняемым** в `run`. Если для
     воспроизведения ошибки нужен обходной приём (`new Function`), это
     допустимо, но видимый код и комментарий-ожидание должны соответствовать
     реальному выводу
   - **демо обязано показывать заявленное**: если текст обещает «этот компонент
     не рендерится» — проверь (тестом или логикой), что при рендере родителя он
     действительно не рендерится; при необходимости обернуть в `memo` и вынести
     поддерево из рендера, объяснив это на странице
4. **`<Gotchas items={[...]}>`** — «Где могут подловить»: 3–6 ловушек,
   каждая = `{ title: "«Вопрос-подлянка»", code: "мини-сниппет с ответом в комменте", text: "что проверяют + как ответить правильно" }`
5. Если у темы есть известный red flag — блок `<div className="redflag">`:
   **что говорят → почему это red flag → правильная формулировка**
6. Финал — `<div className="explain">` с «Резюме одной строкой».

## Импорты

```jsx
import { Demo } from "./JsDemo.jsx"; // из папки js/; из других папок — путь поправить
import { InterviewQuestion, ModelAnswer, SectionTitle, Gotchas } from "../InterviewBlocks.jsx";
```

## Правила

- ВСЯ страница двуязычная (тумблер RU/EN в сайдбаре, LangContext):
  - вопрос/ответ — пропсы en (см. выше);
  - произвольный текст (карточки, hint, explain, redflag) — обёртка
    `<L ru={<>…</>} en={<>…</>} />` из InterviewBlocks;
  - блоки кода — `<CodeBlock ru={`…`} en={`…`} />` (код одинаковый,
    переводятся КОММЕНТАРИИ и строковые литералы-сообщения);
  - `Demo` — проп `en={{ title, code, hint }}`; `Reveal` — `en={{ note }}`;
  - `Gotchas` items — поле `en: { title, code, text }`;
  - `SectionTitle` — типовые заголовки переводятся сами, свой — проп `en`.
  Термины (hoisting, TDZ, batching) в русском тексте — по-английски.
- НЕ переводить термины дословными кальками: «first-class citizens» — это
  «объекты первого класса» или английский термин, но не «граждане первого
  класса». Сомневаешься, как термин звучит по-русски, — оставляй английский.
- В `Demo.run` НЕ использовать `eval` (rolldown ругается) — для воспроизведения
  ошибок использовать `new Function("...")()`.
- Ошибки в демо ловятся автоматически (Demo оборачивает run в try/catch).
- Новую тему зарегистрировать в `src/App.jsx` в SECTIONS (порядок секций:
  JS Core → React → Redux → ... → Тренировка → Разное).
- К новой теме добавить 2–3 вопроса в квиз `src/quiz/questions.js`
  (формат `{ t, q, o[4], a, e }`), соблюдая порядок тем в банке.
- После изменений: `cd react-interview && npm run build && npm test` — оба
  зелёные. В `npm test` входит СТРАЖ ПЕРЕВОДОВ
  (`src/__tests__/translations.test.js`): он падает, если на любой странице
  у `InterviewQuestion` или `ModelAnswer` нет пропа `en`. Страница без
  EN-перевода не считается готовой — перевод пишется сразу, не «потом».

## Стили (уже в App.css)

`.q-block` / `.answer-block` / `.q-label` — вопрос и ответ; `.card`, `.explain`
(синий, резюме), `.redflag` (красный), `.hint`, `.badge`, `pre.code`, `.log`.
